# YUSUKE IKEDA — DESIGN BOOK

この資料は、提供された [制作指示書](BRIEF.md) をページ・UI・更新方法に落とし込む設計書です。実装の検証結果は [VALIDATION.md](VALIDATION.md)、各要件との対応は [REQUIREMENTS.md](REQUIREMENTS.md) に記録します。

## 1. ブランドと目的

**RACING × HUMAN × MOMENTUM**
**速さだけではない。挑戦を追いたくなる。**

現在地は「全日本ロードレース選手権に挑戦するロードレーサー、池田優介」。世界選手権への参戦、未確認の戦績、本人が語っていない経験は作りません。宮城県角田市という出発点と、レースの前後にある人間の時間を伝える場所として設計します。

ファンには「人物を知る → 挑戦を追う → レースを見る → 応援する」、企業には「活動を理解する → 取り組みを考える → 相談する」という自然な道筋を用意します。支援方法や費用の説明を省略した寄付ボタン、根拠のない数字、誤認を招く仮の企業ロゴは掲載しません。

### 良い点・悪い点を検討するための設計仮説

以下は上記サイトに対する実地評価ではなく、依頼書が求める競技ブランド・自動車ブランド・個人アスリートの情報構造から導いた設計判断です。取得可能な環境で、公開前に実地の比較調査を追加できます。

| 検討する型         | 有効な考え方                             | この案件で避けたいこと                           | 池田優介への再解釈                             |
| ------------------ | ---------------------------------------- | ------------------------------------------------ | ---------------------------------------------- |
| レーシングチーム   | 次戦・結果がすぐ分かり、シーズンを追える | 競技データが先行し、初見では人物が分からなくなる | ヒーロー直下に次戦、その後に人物とストーリー   |
| 自動車ブランド     | 大きな写真と余白で対象への興味を作る     | 動画や演出が重く、携帯回線で本文に届かない       | 軽量な本人写真、短いフェード、通常のスクロール |
| 個人アスリート     | 本人の表情・言葉・日常を軸に関係を作る   | 未確認の人物像や成果を広告コピーで補う           | 本人提供の言葉をJSONへ。未提供時は未掲載と明示 |
| スポーツメディア   | 日付・種別・見出しで継続的に追いやすい   | 同じカードの大量配置で写真と情報の序列が弱くなる | ニュースは編集的な行組み、写真は大きなJournal  |
| 企業パートナー資料 | 活動・用途・成果・窓口が比較できる       | 架空の閲覧数や過剰な露出効果を示す               | 確認済み期間付き実績だけ表示し、個別相談へ     |

他サイトのロゴ、画像、コード、固有のレイアウトは流用しません。

## 7. デザインシステム

**EDITORIAL MOTORSPORT DESIGN**。角を丸めたカードの反復ではなく、写真、長短の文章、大きな数字、線、余白で情報の序列を作ります。

| トークン     | 値        | 主な用途                        |
| ------------ | --------- | ------------------------------- |
| Racing Blue  | `#0066FF` | 次戦、CTA、ブランドのアクセント |
| Deep Blue    | `#0047CC` | 青い面の操作状態                |
| Off White    | `#F7F8FA` | ストーリー・ニュース            |
| White        | `#FFFFFF` | プロフィール・サポート          |
| Light Gray   | `#E9EDF2` | 区切り・写真素材待ちの面        |
| Racing Black | `#08090B` | レース・フッター                |
| Carbon       | `#111318` | 暗い面の補助                    |
| Dark Navy    | `#0B1324` | ヒーロー・企業パートナー        |

色、コンテナ幅、ヘッダー高、余白はCSS Variablesで管理します。欧文のブランド表示はBarlow Condensed、和文はNoto Sans JPを基本とし、ローカルフォントとシステムフォントのフォールバックで外部接続を減らします。巨大文字は`clamp()`で画面幅に応じて調整します。

### 再利用する部品

セクション見出し、テキストリンク、塗りボタン・枠ボタン、レース詳細、ニュース行、SNSリンク、写真とクレジット、パートナーロゴ、未登録・読み込み失敗の表示を共通化します。競技データや本文はJSONとJavaScriptで扱い、定期更新のたびにHTMLを書き換える構造を避けます。

## 8. スマートフォン・タブレット・PC

- **320px / 390px**：1列主体。ロゴ・SNS・MENU、短いコピー、44px以上を目安にした操作領域。写真は幅いっぱい。長い英語・URLでも横スクロールを出さない。
- **768px**：内容に応じて1列と2列を使い分ける。見出しと写真の最小幅を優先し、無理にPCナビゲーションを縮めない。
- **1366px**：左右の余白を大きく取り、人物・企業セクションの非対称な組版を見せる。次戦情報は一度に読み取れる帯にする。
- **1920px**：本文を際限なく広げず、写真と大見出しの迫力を保ちながら読み幅を制御する。

メニュー、ニュース絞り込み、大会詳細はキーボードで操作できます。フォーカスを視認できる状態にし、動きを減らす設定に合わせて自動切替を抑えます。スクロールジャックや長い導入演出は行いません。

## 9. 写真とモーション

本人写真はまだ提供されていません。現時点の写真枠は「本人写真が未提供」であると判別できる表現です。AI生成写真、別のライダー、架空の本人ポートレートは使用しません。

写真受領後は、レース走行・ヘルメット・スタート前・ピット・人物の3〜5枚を選び、約6秒間隔のクロスフェードで見せます。停止・再生操作、非表示タブでの停止、`prefers-reduced-motion`に対応します。過剰な加工を避け、文字の読みやすさに必要な範囲だけオーバーレイを使用します。

本文写真はWebP / AVIFを優先し、寸法、`srcset` / `sizes`、遅延読み込みを指定できるようにします。写真の著作権・肖像・撮影者クレジットを確認します。

## 10. 公開前に埋める本人情報

実装が動くことと、実在する本人の情報が揃っていることを区別します。次は制作指示書だけでは確定できません。

1. 本人写真と使用許諾、撮影者クレジット。
2. 本人が確認した経歴と「なぜ走るのか」の言葉。
3. 参戦予定、クラス、公式日程、リザルト。
4. 本人確認済みのInstagram / X / Threads / Facebook URL。
5. 公開するニュース原稿・日付・写真。
6. パートナーの掲載許諾、ロゴ、公開可能な実績数値と集計期間。
7. Google Formsの公開URL、運営者、取得項目、保存期間、連絡先。
8. 実際に支援を受け付ける場合の方法・条件・報告方法。

これらの未提供項目を架空のデータで埋めることは、制作指示書の正確性・本人写真・実績数値の方針に反します。現在は未登録状態として表示し、受領後にJSONで反映します。
